# v0.14.2 — No more LOADING hang, the same crowd for everyone

## For players

- **Fixed: the game could hang on the LOADING screen at start-up** (seen with HD packs on).
  Windows raised the game's main thread so high, while it waited on the graphics, that the
  game's other threads, which share one processor core, never got to run. A watcher now lets
  such a starved thread run on another core until it has had its turn
  (`RECOMP_STARVE_WATCH=0` turns it off).
- **Online: the background crowd is the same on every player's screen.** It used to animate
  differently on each; the fight itself was never affected.
- Everyone in an online match needs this version: the lobby refuses players whose builds
  differ.

## Under the hood

- Toolkit `kernel_starve.c`: every 200 ms, pinned game threads that have been ready to run
  for 600 ms without a context switch may use every core until they have run.
- `crowd_control.c` in lockstep play: the background crowd counts only the updates that run,
  gets one frame's time per update while loading and once per fight step after, draws from a
  private `rand` seed in its set-up and updates, and runs 4 updates while loading and the
  other 596 at the first fight step, once its data has loaded
  ([findings](../research/crowd-nondeterminism.md#the-background-crowd-in-lockstep-play-2026-11-04)).

Toolkit: `2c677a9` (ScikuVRC/xboxrecomp). Setup compiles the player's verified supported USA
Xbox dump locally; no game executable or game assets are distributed.
